# Инструкция для Notebook LLM

## Цель

Создать **презентацию** (слайды) о демонстрационной системе **WMS «Атамекен-Агро»** — веб-кабинет и мобильный ТСД для управления складом агрохимии.

## Аудитория

Руководители и стейкхолдеры: менеджмент, закупки, складская служба, ИТ. Уровень — обзорный, без глубокого кода.

## Язык

**Русский** — весь текст слайдов, заголовки, подписи к диаграммам.

## Источники в этом бандле

Используй **все** приложенные файлы:

| Файл | Назначение |
|------|------------|
| `docs/canister-journey-scenario.md` | **Главный сценарий** — сквозной маршрут канистры `341X1302R9S18` |
| `PRESENTATION_STYLE.md` | Дизайн-система слайдов (цвета, шрифты, тон) |
| `PROJECT_OVERVIEW.md` | Краткое описание продукта |
| `ARCHITECTURE.md` | Модули, роли, доменная модель |

## Содержание презентации (рекомендуемая структура)

1. **Титульный слайд** — WMS «Атамекен-Агро», демо для стейкхолдеров.
2. **Проблема и ценность** — прослеживаемость канистр от закупки до утилизации.
3. **Архитектура решения** — 5 модулей (Главная, Снабжение, Склады, Сканирование, Отчёты), веб + ТСД.
4. **Роли пользователей** — OTP 666/111/222/333 и их зоны ответственности.
5. **Цепочка снабжения** — ЗН-006 → сводная → Упак → ОП-001.
6. **Главный склад** — приёмка палеты, размещение A-01-03, отбор ОТБ-001.
7. **Перемещение на дочерний склад** — маршрут ГС → ДС №1.
8. **Выдача агроному и возврат** — ТСД, акты, пустая тара.
9. **Утилизация** — зона утиля, списание, закрытие цикла.
10. **Дашборд и отчёты** — KPI, история канистры, PDF.
11. **Демо-объекты** — таблица SN, SSCC, документов.
12. **Следующие шаги** — пилот, интеграции, масштабирование.

## Ключевой сюжет

Проведи аудиторию по **одной канистре** `341X1302R9S18` (Торнадо 540) через весь цикл:

**ЗН-006 → ОП-001 → ГС (приёмка/хранение/отбор) → перемещение → ДС → выдача → возврат → утилизация.**

## Стиль

Строго следуй `PRESENTATION_STYLE.md`: корпоративный B2B-интерфейс, синий акцент `#2A48FF`, светлый фон, чёткая типографика Segoe UI, минимум декора.

## Формат выхода

- 12–18 слайдов.
- На каждом слайде: заголовок, 3–5 тезисов или одна схема.
- Для процессных слайдов — горизонтальный пайплайн (как в UI `dash-pipeline`).
- Укажи, какой OTP/роль демонстрирует этап.
- Не выдумывай данные — только из сценария и архитектуры бандла.

## Чего избегать

- Технический жаргон (React, TypeScript) на слайдах для бизнеса.
- Тёмная тема и неоновые градиенты.
- Выдуманные номера документов и коды, не указанные в сценарии.
